# Мета
Реалізувати зчитування коментарів з файлів формату `tc<NNN><UID>.md` в директорії тікета, підтримку YAML frontmatter для коментарів, парсинг прив'язок до інших тікетів (references), та сортування коментарів за часом створення (від найстаріших до найновіших). Це покриває перші чотири підпункти з розділу "Ticket Comments" у `TODO.md`.

# Зміни
1.  **Структури даних (`src/model.rs`)**:
    *   Створити структури `CommentMetadata` (для десеріалізації YAML) та `Comment`.
    *   `CommentMetadata` повинна містити: `author` (String), `created_at` (DateTime<Utc>), `updated_at` (Option<DateTime<Utc>>), `attachments` (Option<Vec<String>>).
    *   `Comment` повинна містити: `id` (з імені файлу, наприклад `tc001abc`), `metadata` (CommentMetadata), `content` (String), та `references` (Vec<String>).
    *   Додати поле `comments: Vec<Comment>` до структури `Ticket`.

2.  **Зчитування та парсинг (`src/model.rs` або окремий модуль)**:
    *   Модифікувати процес завантаження тікета (`Ticket::load` або схожий метод).
    *   Додати пошук файлів за маскою `tc*.md` у директорії тікета.
    *   Для кожного знайденого файлу зчитувати вміст, відділяти YAML frontmatter від Markdown тексту (використовуючи існуючий підхід або крейт на кшталт `gray_matter`).
    *   Використовувати існуючу логіку парсингу ticket references (ідентифікатори `#abc123`) для витягування посилань з тексту коментаря.
    *   Сортувати зібраний вектор `comments` за полем `created_at` (за зростанням).

3.  **Інтеграція в Slint (`ui/app.slint` та `src/main.rs`)**:
    *   Додати відповідні структури до Slint об'єктів (наприклад, `Comment` struct в `.slint`).
    *   Передати завантажені коментарі через міст між Rust та Slint при відображенні детальної інформації про тікет (хоча повне відображення буде в наступному таску "Update UI", дані вже мають бути доступні в моделі Slint).

# Тести
1.  **Unit Tests (`src/model.rs` або `tests/`)**:
    *   Тест на коректне зчитування директорії тікета з кількома файлами `tc*.md`.
    *   Тест на парсинг YAML frontmatter коментаря.
    *   Тест на витягування ticket references з тексту коментаря.
    *   Тест на правильне сортування коментарів (older first).
    *   Тест на обробку помилкових файлів коментарів (без frontmatter, з неправильним форматом дати).

# Ручна перевірка
1.  Створити тікет через UI або CLI.
2.  Перейти в директорію тікета на файловій системі.
3.  Створити файли `tc001aaa.md` та `tc002bbb.md` з коректним YAML frontmatter (різні дати `created_at`) та текстом, який містить посилання на інший тікет (наприклад, `#test01`).
4.  Запустити програму.
5.  Поки що UI може не відображати коментарі повноцінно, але можна додати логування або перевірити на рівні `cargo test`, що дані успішно завантажуються в модель.
