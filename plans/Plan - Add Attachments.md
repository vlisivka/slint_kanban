# Plan - Add Attachments

## Мета
Реалізувати можливість прикріплювати файли до тікетів та коментарів без збереження їх як окремих полів (масивів) у метаданих YAML. Усі файли копіюватимуться до єдиної підпапки `attachment/` всередині директорії тікета. 
Замість складної прив'язки, при натисканні на кнопку додавання долучення в UI, файл копіюватиметься до директорії, а в текстове поле (опис тікета або поле нового коментаря) буде автоматично вставлятися Markdown-посилання на цей файл (наприклад, `[image.png](attachment/image.png)`). 
Повноцінний перегляд таких Markdown-посилань буде реалізований у наступних задачах, тому зараз додамо базову кнопку "Open Attachment Folder" для перегляду долучень у файловому менеджері ОС.

## Зміни
1. **Залежності (`Cargo.toml`)**:
   - Додати crate `rfd` для нативного кросплатформного діалогу вибору файлів.
   - Додати crate `open` для реалізації кнопки швидкого відкриття папки долучень у файловому менеджері ОС.

2. **Модель (`src/model/board.rs`, `src/model/ticket.rs`)**:
   - Створити метод `Board::attach_file(&self, ticket_id: &str, source_path: &std::path::Path) -> anyhow::Result<String>`, який буде:
     - Перевіряти наявність папки `attachment/` в папці відповідного тікета та створювати її за потреби.
     - Формувати ім'я цільового файлу. Якщо файл з таким іменем вже існує, додавати суфікс ` (1)`, ` (2)` тощо перед розширенням файлу.
     - Копіювати файл.
     - Повертати згенероване Markdown-посилання на файл (наприклад, `[filename.ext](attachment/filename.ext)`).

3. **Контролер та UI-міст (`src/controller.rs`, `src/main.rs`)**:
   - Додати обробники повернення значень у Slint (callbacks, що повертають `string`):
     - `on_attach_file(ticket_id: string)` -> `string`: викликає діалог `rfd::FileDialog`, при успішному виборі файлу викликає логіку моделі та повертає сформований Markdown-текст (або порожній рядок, якщо вибір скасовано).
     - `on_open_attachment_folder(ticket_id: string)`: відкриває `attachment/` папку тікета у системному файловому менеджері за допомогою crate `open`.

4. **Інтерфейс (`ui/dialogs/ticket_edit.slint`, `ui/dialogs/ticket_view.slint`, `ui/common.slint`)**:
   - В `TicketStr`: додати поле `attachment_count: int`, яке вказуватиме загальну кількість файлів у папці `attachment/`.
   - В `main.rs`: під час конвертації `into_slint_ticket`, просканувати директорію `<Ticket_ID>/attachment/` та підрахувати файли (ігноруючи підпапки).
   - У `TicketEdit`: додати кнопку "Attach File" (наприклад, поруч із базовими кнопками або під текстовим полем). Після натискання викликається `attach-file`, і якщо результат не порожній, до `description_text` дописується повернутий Markdown рядок (через перенос рядка).
   - У `TicketView`: 
     - Додати кнопку "Attach File" поруч із кнопкою "Post Comment". Вона так само викликає подію і дописує отриманий Markdown текст у `comment_input.text`.
     - Додати кнопку "📁 Attachments (N)" зверху (поруч із "Edit" та "Close"), де `N` — це `ticket.attachment_count`. Кнопка викликатиме подію відкриття папки `attachment/` в ОС. Якщо `N == 0`, можна приховати кнопку або показувати "0".

## Автоматичні тести
- **Unit тести** (`src/model/tests/board_tests.rs`):
  - Перевірка логіки копіювання файлу, створення підпапки `attachment/` та повернення коректного Markdown тексту.
  - Перевірка генерації імен з суфіксами під час колізій імен (наприклад, створення трьох файлів, з перевіркою виникнення `test (1).txt`, `test (2).txt`).
- **CLI тести** (`src/main_tests.rs`):
  - Додати підтримку CLI: `cargo run -- attach --id <ID> --file <PATH>`, яка копіює файл та виводить Markdown рядок у stdout. 
  - Написати інтеграційний тест `test_cli_attach`, що перевіряє цей процес.
- **GUI тести** (`src/gui_tests.rs`):
  - Перевірити запис відформотованого шляху шляхом симуляції. Нативні діалоги `rfd` блокують потік, тому сам діалог не можна викликати безпосередньо. Але можна додати тестовий callback `invoke_test_attach_file_return`, щоб перевірити, чи коректно оновлюється текст у Slint компонентах після повернення значення.

## Ручна перевірка
1. Клікнути на тікет та натиснути "Edit".
2. Натиснути кнопку "Attach File", вибрати файл (наприклад, `image.png`). Перевірити, чи з'явився новий рядок текст `[image.png](attachment/image.png)` в описі. Зберегти тікет.
3. У вікні перегляду тікета звернути увагу на новий коментар: натиснути "Attach File" біля поля вводу, вибрати той самий `image.png`. Текст має з'явитися у полі вводу. Дописати текст коментаря і натиснути "Post Comment".
4. Перевірити файлову систему: в папці тікета має з'явитися `attachment/image.png` та `attachment/image (1).png`.
5. Натиснути кнопку "📁 Attachments" у `TicketView`. Має відкритися системний файловий менеджер, у якому будуть розміщені вказані файли.
