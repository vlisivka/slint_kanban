# План реалізації - Burndown Charts

Цей план описує впровадження графіків Burndown для відстеження прогресу виконання задач у спринтах.

## Мета
Додати візуалізацію "Burndown Chart" (графік згоряння задач) до розділу статистики. Графік має показувати кількість залишкових "points" на кожен день поточного спринту порівняно з ідеальною лінією прогресу.

## Зміни

### 1. Модель статистики (`src/model/stats.rs`)
- Додати структуру `BurndownPoint`:
  ```rust
  #[derive(Debug, Clone, PartialEq)]
  pub struct BurndownPoint {
      pub date: String,
      pub remaining_points: u32,
      pub ideal_points: u32,
  }
  ```
- Додати поле `burndown: Vec<BurndownPoint>` до структури `BoardSummary`.
- Оновити функцію `get_board_summary` для розрахунку даних графіка:
    - Визначити поточний спринт.
    - Визначити обсяг робіт (scope) спринту: усі тікети, які мали активність протягом спринту (автоматично включає нові тікети).
    - Для кожного дня спринту (від `start_date` до `end_date` або сьогодні):
        - Розрахувати суму балів усіх тікетів у скоупі.
        - Відняти бали тікетів, які були переведені в статус "Done" до кінця цього дня (використовуючи логи).
        - Розрахувати ідеальну лінію: `total_points * (remaining_days / total_days)`.

### 2. Спільні типи Slint (`ui/common.slint`)
- Додати структуру `BurndownPointStr`:
  ```slint
  export struct BurndownPointStr {
      date: string,
      remaining_points: int,
      ideal_points: int,
  }
  ```
- Оновити `BoardSummaryStr`, додавши `burndown: [BurndownPointStr]`.

### 3. Міст між Rust та Slint (`src/lib.rs`)
- Оновити функцію `into_slint_summary`, щоб вона заповнювала масив `burndown`.

### 4. Інтерфейс статистики (`ui/stats_view.slint`)
- Додати нову секцію "== Sprint Burndown Chart ==".
- Візуалізувати графік. Оскільки Slint не має вбудованих діаграм, використаємо підхід з `for ... in` та прямокутниками (аналогічно до трендів), але з двома лініями або двома стовпчиками (реальні бали vs ідеальні).
- Додати легенду.

## Тести
- **Unit tests** в `src/model/stats.rs`:
    - Перевірити коректність розрахунку балів на конкретні дати на основі мокових логів.
    - Перевірити розрахунок ідеальної лінії (крайові випадки: початок спринту, кінець спринту, спринт на один день).
- **Integration tests**:
    - Перевірити, що при запуску `stats` через CLI або GUI дані з'являються.

## Ручна перевірка
1.  Запустити додаток.
2.  Створити спринт (якщо немає).
3.  Додати тікети з балами.
4.  Перемістити частину тікетів у "Done".
5.  Відкрити "Statistics" та перевірити графік Burndown.
6.  Перевірити, чи ідеальна лінія виглядає як пряма від максимуму до нуля.
