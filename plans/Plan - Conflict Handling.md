# Plan - Conflict Handling in Multi-User Setup

## Мета
Забезпечити стабільну роботу додатка в умовах децентралізованої синхронізації (Git/Dropbox), мінімізуючи ймовірність одночасного редагування однакових файлів та автоматично виправляючи помилки структури черг.

## Зміни

### 1. Модель даних (`src/model/config.rs`)
- Додати поле `manage_only_mine: bool` до структури `UserConfig`.
- Встановити значення за замовчуванням `true`.
- Оновити логіку серіалізації/десеріалізації для завантаження цієї опції з `user.toml`.

### 2. Запобігання конфліктам (GUI та CLI)
- **AppController (`src/app.rs`)**:
    - Додати логіку перевірки прав: тикет можна редагувати або переміщувати лише якщо він призначений на `active_user` АБО якщо деактивовано режим «редагувати лише мої тікети».
- **UI (`ui/app.slint`)**:
    - Додати опцію в настройки для зняття прапорця manage_only_mine.
    - Візуально блокувати можливість перетягування (`TouchArea` або `enabled` властивість) для чужих тикетів, якщо `manage_only_mine` увімкнено.
    - Вимкнути кнопку "Edit" у `TicketView` для тикетів, якими користувач не може керувати.
- **CLI (`src/main.rs`)**:
    - У командах `update`, `move`, `remove` додати перевірку прав перед виконанням дії. Якщо доступ заборонено — виводити чітке повідомлення про помилку.

### 3. Автоматичне вирішення конфліктів черг (`src/model/mod.rs`)
- Оновити `Board::load` для виконання наступних перевірок:
    - **Видалення дублікатів**: Якщо один і той самий тикет знайдено у кількох чергах, залишити лише симлінк у тій черзі, яка знаходиться найдалі за порядком (має найбільший індекс). Інші симлінки видалити.
    - **Приєднання "сиріт"**: Якщо в директорії `Tickets/` знайдено тикет, на який не посилається жодна черга, автоматично створити для нього симлінк у першій доступній черзі.
    - **Очищення сміття**: Видаляти невалідні симлінки в чергах, що посилаються на неіснуючі тикети.

### 4. Режим адміністратора
- Реалізувати підтримку прапорця `--no-manage-only-mine` у CLI.

## Тести

### Автоматичні тести
- **Unit (src/model/config.rs)**: Тестування міграції конфігурації та збереження нової опції.
- **Unit (src/model/mod.rs)**:
    - Тест: Тикет у двох чергах -> після завантаження має залишитися лише в останній.
    - Тест: Тикет без черги -> після завантаження має з'явитися в першій черзі.
    - Тест: Битий симлінк -> має бути видалений.
- **Integration (CLI)**:
    - Спроба перемістити чужий тикет при `manage_only_mine = true` має завершуватись помилкою.
    - Команда `stats` має продовжувати працювати для всіх тикетів незалежно від прав.

## Ручна перевірка
1. Активувати `manage_only_mine` в `user.toml`.
2. Спробувати змінити статус тикета, який призначено на іншого користувача через GUI.
3. Вручну створити дублікат симлінка через термінал: `ln -s ... Queue/1.Incoming/abc && ln -s ... Queue/2.ToDo/abc`. Запустити додаток і перевірити, що тикет залишився лише в "ToDo".
4. Спробувати завантажити "осиротілий" тикет і переконатись, що він з'явився в "Incoming".
